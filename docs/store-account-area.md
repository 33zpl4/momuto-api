# Store account area — what a buyer sees, what we changed, what is open (19 Oct 2026)

Owner question: "the buyer who ordered should be able to check the order clearly on their own store (www / us / es / fr / it): clean account, order details, tracking number."
Everything below was measured on the LIVE stores from a GitHub runner (the sandbox cannot reach them) with `scripts/probe-store-account.js`; test customer on the US store.

## 1. There are three order surfaces (they do not know each other)

| surface | URL | reached from | login | shows |
|---|---|---|---|---|
| **Store account** (platform theme) | `<store>/account/login`, `/account`, `/account/orders`, `/account/orders/<order no.>` | the platform's own emails ("on the way", paid...) and typing the URL. **Nothing on the stores links to it** (see section 3) | the store's customer account (per store) | status, order no., date, total, shipping method, payment, addresses, **Tracking** (carrier : number + the carrier's homepage, only after the platform marks it shipped), product table, totals, *Buy Again* |
| **Design-server account** | `design.momuto.com/login`, `/userInfo/order` | the header person icon and (US) the footer "Order Status" on every store | design-server member login (a different account system) | `server-patches`/`templates/*/userinfo/*` templates, rows from a PHP action that is NOT in any repo |
| **"My order"** (ours) | `/pages/my-order` · `mi-pedido` · `mon-commande` · `il-mio-ordine` | our lifecycle emails only (`docs/order-view.md`) | none: ref + token or ref + email | design renders, roster, timeline, window, tracking **from our admin**, the "Share your new kit" card |

Tracking lives in two unconnected places: the **platform** (Ship dialog: carrier + number; shown on the store account page) and **our admin** (`public/admin.html` → KV; shown in our tracking email and "My order"). The team enters it twice. Whether the platform's order API returns carrier + number (so we could fill ours automatically) is NOT checked.

## 2. Verified facts (US store unless stated)
- Header: the visible account icon is `a.account_icon.to3d` → `https://design.momuto.com/login` (ES/FR add `?lang=`); the platform's own icon (`a.account_icon.login`) is hidden by the live custom CSS (`docs/store-theme-css.md`). Same on all five stores. FR also has an "S'inscrire" → `/account/login` link in the mobile menu.
- Footer "Order Status" → `design.momuto.com/userInfo/order` (owner, US). Other stores not checked.
- `/account/login` and `/account/register` exist and are localized on all five stores; logged out, `/account` and `/account/orders` redirect to `/account/login`.
- "My order" is live (HTTP 200, form renders, no duplicate visible title) on all five.
- Login control is a script div (`div#confirm.main_btn.form_btn`), not a submit button.
- After sign-in the platform shows: My Account (5 buttons) → My Orders (status filter + order search, one card per order, *Buy Again* / *Click to view*) → Order Detail.
- Order Detail of a shipped order: badge SHIPPED, order no., date, total, *Buy Again*, shipping method / payment / shipping + billing address, **Tracking** block (`div.tracking-warp` › `.tracking-header`, `.tracking-item-title` "USPS : <number>", `.tracking-item-des` = `http://www.usps.com/`, the carrier's HOMEPAGE, not a tracking link), product table, totals. The product picture is an empty grey box here (the order list shows it).
- Platform courier list (`GET /couriers`, US token): 3,459 carriers; **USPS = id 4629, code 21051**; the admin's Ship dialog offers it under "Common logistics" once pinned (`sync-store-config.js` `MODE=inspect-couriers`, workflow *Store Config*, read-only).
- Platform emails (dump in `cms/email-notifications/`): **"order shipped" (`orders-fulfilled`) is the platform's English default on ES, English text on IT, French on FR, custom English on EN/US; "delivered" (`orders-confirm-receipt`) is English on ES (active), French on FR (active), off on IT/EN/US.** The middle of those emails (tracking button, "view order") is generated by the platform and not in our dump, so where its button points is unverified.

## 3. What we built (branch `claude/keen-darwin-52lbrf`, NOT LIVE)
- `docs/account-brand/account-brand.css` + `account-brand.js` (+ `README.md`, `preview-snippet.js`): a dark brand skin for the five platform account pages and a **tracking panel moved to the top** of Order Detail (carrier, big number, *Track package*, *Copy number*; USPS/UPS/DHL/FedEx open the carrier page with the number). Scoped with `:has()` to the five account containers, so no other page changes. Verified on the live US store, desktop and 390 px. **To go live: paste `docs/account-brand/account-brand-entry.html` (generated by `scripts/build-account-brand-entry.js`) as ONE NEW script-manager entry named `MOMUTO account skin v1`, identical in each of the 5 stores (owner ruling 19 Oct 2026; not inside the nav script); see `docs/account-brand/README.md`.**
- The share-image link in our emails and on "My order" (`docs/order-view.md`) — merged earlier (momuto-api#338, design-momuto#237).
- `scripts/probe-store-account.js` + workflow *Probe store account area (read-only)*: header/footer links, account URLs, the "My order" pages, optional logged-in pages (repo secrets `STORE_<WWW|US|ES|FR|IT>_EMAIL` / `_PASSWORD`; only US is set). Run it with `css=none js=none` to see which stores have the entry pasted (`account skin: v1` / `NOT PASTED`), computed styles, DOM outline, page markup, CSS/JS injection (`PROBE_CSS`, `PROBE_JS`), the click-through to the carrier page, screenshots. Screenshots of the test account go to a throwaway branch `probe-account-shots` ONLY when the workflow is dispatched with `publish_shots=true`; any other run deletes that branch. Until the workflow file is on `main` it runs on a push to the branch (remove the `push:` block when merging).

## 4. Open decisions / follow-ups (nothing below is done)
1. **Header icon target:** keep `design.momuto.com/login` or point it to the store's `/account` (theme setting; only the owner can edit).
2. **Footer "Order Status":** same question; it is a navigation item (`sync-store-config.js` `apply-nav`, dry run first).
3. **Platform shipping/delivered emails:** translate ES and IT, add a link to "My order" (write to live customer emails: ask first; `push-recovery-email.js` is the pattern).
4. **Tracking entered twice:** probe the platform order API (`GET /orders/{id}`) for carrier + number; if present, fill our admin record automatically.
5. *Buy Again* on a custom-kit order probably does not re-create the design (restyled, not hidden).
6. Not styled / not captured: the "Registered successfully" popup, Address Book, My Profile, Change Password, the empty-orders state.
7. Safari/iOS, Firefox, the other four stores, carriers other than USPS, and a real carrier page with a real number are untested (USPS answers the runner `403 Access Denied`; click the button once on a phone).
